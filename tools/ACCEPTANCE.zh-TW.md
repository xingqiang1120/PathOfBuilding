# 生成器驗收標準（2026-11-26 訂）

每次生成器改版（GENERATOR_VERSION），都要用同一份「考卷」打分數，才知道是真的變好，還是只換了一種樣子。
考卷：`tools/data/benchmark.json`。執行：`python tools/benchmark.py run --jobs 4`（約 50 分鐘，下班後或空檔跑）。
結果：`library/benchmark/v<版本>.md`（和上一版自動比較）。

## 自動驗收（每版都跑）

| # | 檢查 | 怎麼算 | 及格 |
|---|---|---|---|
| 1 | **跟真人比** | 用真人作者自己的裝備（`--gear-from`），生成器重建天賦樹、寶石、光環、設定，跟作者原本的 build 比 | DPS ≥ 作者的 80%，而且防禦分數 ≥ 作者 − 0.1（不比總分：作者常沒補滿抗性，扣分會讓生成器「贏」卻只有九分之一傷害） |
| 2 | **可玩門檻** | 固定 10 組模板組合，每個 build 都要能打圖（95 級） | 元素抗性 75%、混沌抗性 ≥ 0（或免疫）、生命＋能量護盾 ≥ 4,000、最小的最大承受 ≥ 8,000 |
| 3 | **不退步** | 同一組合跟上一版比分數 | 下降不超過 0.05；超過要說明原因或修正 |
| 4 | **權重預測** | `python tools/weights.py check`：保留 20% 模擬不學，看權重能不能猜中最好的選擇 | 各類別「前 3 名命中率」不低於上一次 |

評分公式（生成器自己用的）：ln(DPS) + 防禦 − 扣分。
- 防禦 = (ln EHP + ln 最小的最大承受) / 2 + 0.2 × ln(1 + 每秒回復 %)。
- 扣分：抗性沒滿、屬性不夠、保留超過、混沌抗性 < 60%。
- 真人穿著有特性檔案的傳奇（例如 Doryani's Prototype）時，兩邊都照特性檔案扣分（閃電抗性不扣）。

已知會吃虧的地方（報告會列出）：
- 生成器還不會放天賦樹珠寶以外的珠寶（星團珠寶、永恆珠寶），用作者裝備時這些會被拿掉。
- 作者 build 的 Config 是作者自己設定的，生成器用的是推論。
- 作者 build 的 Vaal 技能評分前拿掉（2026-11-27）：PoB 把它當永遠開著，生成器也不選它，留著會讓作者的防禦和 DPS 被高估。

## 人工驗收（使用者）

| # | 檢查 | 怎麼做 |
|---|---|---|
| 5 | **實際遊玩** | 挑生成的 build 進遊戲測。確認過的設定記成「已驗證」（`pob_save_build_settings`），和 PoB 不同的地方記下來改進。 |
| 6 | **玩家眼光** | 生成的 build 有沒有「怪怪的」地方：明顯不會有人這樣點、裝備不合理、技能不會這樣用。 |
